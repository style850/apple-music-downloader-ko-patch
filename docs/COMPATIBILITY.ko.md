# 한국어 호환 패치 3.0.1 기준

## 적용 대상

3.0.1은 Windows x64의 Apple Music Downloader Native 설치 폴더를 대상으로 합니다. 기본 경로는 다음과 같습니다.

```text
%LOCALAPPDATA%\Programs\Apple Music Downloader Native
```

다른 위치에 설치했다면 GUI에서 원본 앱 EXE를 선택하거나 `--install-dir`에 설치 폴더를 지정합니다. 패처는 원본 앱 실행 파일, `resources\app.asar`, `resources\native-package.json` 세 파일만 대상으로 합니다.

## 적용 전 구조 검사

버전 번호만 보고 적용하지 않습니다. 다음 조건을 모두 확인할 수 있을 때만 적용합니다.

- ASAR의 `package.json`이 예상 원본 패키지 이름과 main 진입점을 가진다.
- `native-package.json`의 schema·버전·UI 영수증이 유효하고 ASAR 속 실제 UI 파일 해시와 맞는다.
- 기존 `native-renderer.js`, `native-login.js`, `native-startup.js`와 각 HTML 진입점이 존재한다.
- 아직 이 패처의 표시층이 붙어 있지 않다.
- 실행 파일에서 ASAR 무결성 헤더를 하나로 식별하고, 변경 뒤의 헤더로 안전하게 교체할 수 있다.

파일이 변조되었거나 새 원본의 UI 구조가 바뀌었거나 헤더 후보가 애매하면 실패합니다. 이때 패처는 파일을 덮어쓰지 않습니다. 최신 버전 호환 여부는 패처를 실행한 시점의 이 검사 결과로만 결정됩니다.

## 변경 범위

적용본에서는 기존 화면 스크립트 세 개의 끝에 한국어 UI 표시층만 추가합니다. ASAR의 파일 목록과 main/preload/service/네이티브 런타임 코드는 그대로 두고, `native-package.json`의 UI 영수증에서 변경된 세 스크립트 SHA-256만 갱신합니다. 실행 파일에는 바뀐 ASAR 무결성 헤더의 해시만 반영합니다.

사용자 프로필, 계정·세션 정보, 다운로드 파일, 설정 데이터, 원본 서비스와 네이티브 런타임은 읽거나 변경하지 않습니다. 트랙·앨범·아티스트·재생목록의 카탈로그 정보와 사용자가 입력하는 검색어·폼 값도 번역 대상이 아닙니다.

## 상태와 명령

| 상태 | `--check` 결과 | `--apply` | `--restore` |
| --- | --- | --- | --- |
| `original` | 새 원본 또는 업데이트 후의 미적용 상태 | 별도 구조·무결성 검사 후 새 백업을 만들어 적용 | 적용 상태가 아니므로 거부 |
| `patched` | 해당 패처가 정확히 적용된 설치본 | 변경 없이 성공 | 원본 세 파일을 복구 |
| `upgradable` | 검증된 3.0.0 패치 또는 교체 전 중단된 업데이트 | 기존 원본 백업으로 3.0.1을 만들어 업데이트 | 원본 세 파일을 복구 |
| `restored` | 백업과 정확히 일치하는 복구본 | 다시 적용 가능 | 적용 상태가 아니므로 거부 |
| `interrupted` | 원본/적용 파일이 섞였지만 동일 작업의 해시만 존재 | 자동 덮어쓰기 거부 | 일치하는 원본으로 복구 시도 |

상태 파일과 현재 세 파일이 일치하지 않으면 예전 파일을 되돌려 새 원본을 덮어쓰지 않습니다. 실행 중인 앱을 발견하거나 설치 폴더 잠금을 얻지 못해도 적용·복구하지 않습니다.

### 패치 3.0.0에서 업데이트

앱을 종료한 뒤 3.0.1의 `--apply` 또는 GUI의 **한국어 패치 업데이트**를 실행합니다. 먼저 원본으로 복구할 필요가 없습니다. 기존 원본 백업과 해시를 검증하고 그 원본에서 새 표시층을 만듭니다. 3.0.0 표시층 위에 3.0.1을 중복 추가하지 않습니다.

교체 전에 상태 파일에 이전·새 적용본의 세 파일 해시를 함께 기록합니다. 파일이 하나도 교체되지 않았다면 다시 업데이트할 수 있고, 일부만 교체되었다면 `interrupted`로 거절하며 원본 복구를 지원합니다. 세 파일 교체가 끝난 상태는 `patched`이며 다음 적용 시 임시 해시 기록을 정리합니다. 일반 교체 오류가 발생하면 이전 적용본과 상태 기록으로 되돌립니다.

## 원본 업데이트와 복구

원본 앱 업데이트 후에는 앱을 종료하고 같은 패처를 수동으로 다시 실행합니다. 패처는 업데이트 프로그램에 등록되지 않으며, 업데이트를 감시하거나 자동 적용하지 않습니다.

업데이트로 설치 파일이 바뀌면 예전 백업은 새 원본의 복구 근거가 아닙니다. 그래서 이전 패치의 `--restore`로 업데이트된 앱을 낮은 버전으로 바꾸지 않습니다. 새 원본이 구조 검사를 통과하면 그 파일의 SHA-256을 기준으로 별도 백업을 만든 뒤 적용합니다.

백업은 다음 위치의 원본 ASAR SHA-256별 폴더에 저장됩니다.

```text
<설치 폴더>\.amdl-ko-overlay-v3\<원본 app.asar SHA-256>\
```

해시별 백업 폴더 안에는 세 원본 프로그램 파일이 있고, 현재 복구 기록은 `<설치 폴더>\.amdl-ko-overlay-v3\state.json`에 있습니다. 이 자료를 삭제·수정하면 복구를 보장할 수 없습니다. `--check`의 상태 표시는 전체 적용 호환성 검사를 대신하지 않습니다.

## 알려진 기준 사례와 한계

현재 설치된 1.0.4 실제 바이너리는 별도 작업 폴더에서 3.0.0→3.0.1 업데이트·반복 적용·복구하여 세 대상 파일이 원래 바이트로 돌아오는 것까지 확인했습니다. 1.0.4와 고정된 1.0.5-beta.5 소스에서 목록을 채운 브라우저 화면 12개도 검증했습니다. 이전 3.0.0의 실제 Electron 시작 화면은 계정 없는 격리 프로필로 확인했습니다. 공개 소스 구조 확인은 실제 beta.5 설치 파일의 적용 성공을 보장하지 않습니다. 원본의 major UI 구조 변경, UI 영수증 형식 변경, 실행 파일 리소스 형식 변경은 안전 거부 사유입니다. 서명된 원본 실행 파일도 변경하지 않고 거절합니다.

3.x는 새 보안 패치가 아닙니다. 1.0.3-beta.4 전용 r2의 세션 파일 권한 수정과 runtime 권한 복구는 최신 버전에 자동 적용되지 않습니다.
